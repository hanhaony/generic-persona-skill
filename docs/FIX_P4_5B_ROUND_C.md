### 2.3 边界（**必须连同结论一起引用**）

> **E1 只验"给定合格的双主体 RELATION claim，代码能产出条目"，不验畸形输入下的鲁棒性。**

> 它**不**证明：摘录错位、主体 ID 越界、参与者不足、claim 维度错标等异常输入也能被正确处理；
> 也**不**等价于"链路对所有输入都通"。E1 通过只说明**写入这一段没有坏**。

## 5. `traits` 为什么是 0（预期，不是缺陷）

真实链路的判定分布：**16 条证据全部 `SINGLE`**（`occurrences=1, distinct_sources=1`，
无来源的推断证据为 `1/0`）。

原因链与方案 §8 的预测**逐环吻合**：

1. 判定键 = (归一化 claim, 主体集合)，组内按 `source_id` 去重（G6-D2）；
2. 去重后 `occurrences` 恒等于来源数；
3. 三份材料正文互不重复（互动页是"合记"，措辞不同）；
4. 归一化只折空白、**不做语义聚类** ⇒ 措辞不同即不同组；
5. ⇒ 每条 `TRAIT` 证据都 `SINGLE` ⇒ 按 AC-7 **绝不进 `traits`** ⇒ `traits = 0`。

因此 G6 的验收目标不是"`traits` 非空"（不可控），而是：

| 改验项 | 实测 |
| --- | --- |
| 每条证据都有 `stability_verdict` | 16/16 ✅ |
| `stability` 列**仍为** `UNKNOWN`（原值未被覆盖） | 16/16 ✅ |
| 无 `STABILITY_UNASSESSED` 告警（判定全部成功，没有静默退回） | ✅ 无 |

这三条正是 G6-D1 那个决策（另开字段、不改原列）的**运行时证据**。

## 7. 一次自我纠正（必须记录）

**现象**：真实运行的日志里出现 1 条 `[FAIL] 稳定性判定未按来源去重
（occurrences != distinct_sources）：['evd_c3ad…']`，脚本以 exit code 3 结束。

**归因**：这条证据是 `INFERENCE`（由 `c6/c8/c9/c10` 四条推导），按证据登记规则
**不带单一来源**（`source_id=None`），因此判定结果是 `occurrences=1 / distinct_sources=0`。
这是**正确结果**，不是去重失效。

**错在哪**：我把 "G6-D2 去重后 occurrences == distinct_sources" 写成了无条件不变式，
漏掉了"无来源的推断证据"这一类。

**怎么修的**：

1. 脚本与复算器两侧都把该检查限定为**只对有 `source_id` 的证据**成立；
2. 对**同一份产物**重新离线复算：**39/39 通过**；
3. **没有重跑 E2**——运行本身没有失败，重跑只会多花一次钱且不增加任何信息。

> 这条记录留在报告里，是因为"把断言写宽以掩盖问题"和"把断言写窄以承认事实"
> 看起来很像。区别在于：这次放宽只针对一类**可解释的正确结果**，且
> `stability` 列未被改写、16/16 都有判定这两条更硬的检查**没有动**。

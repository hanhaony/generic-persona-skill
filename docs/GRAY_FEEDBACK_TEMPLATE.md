# 试用反馈模板（卡住就照这个填）

> **为什么要有模板**：一句"我跑了 chat，没反应"要来回三轮才能定位；
> 按下面填满，通常**一轮就能定位**。
> **别删字段**，没有就写"无"。

---

## 一、五样必填（缺一样就要多问一轮）

```text
1. 命令原文（完整一行，含所有参数）：
   python -m persona ______________________________________________

2. 退出码（bash 用 echo $?；Windows 用 echo %ERRORLEVEL%）：
   ______

3. 输出片段（从第一条异常往前 20 行，一直到末尾；**不要只截 Error 那一行**）：
   > 粘贴在这里
   > ...

4. 环境：
   python --version = ______
   操作系统       = ______

5. 数据（自愿）：`--out` 目录里的 persona.db
   □ 确认不含密钥，可分享   □ 不方便分享（那就直说，我给你几条只读命令自查）
```

---

## 二、三个必答（这三问才是这次灰度真正要的东西）

```text
1. 卡在第几步？（单选）
   □ 第 1 步 run 建档案   □ 第 2 步 chat 对话   □ 第 3 步 跨会话记忆
   性质：□ 先没看懂（文档） □ 跑不通（代码） □ 通了但结果不对（质量）

2. 有没有哪个行为**你以为是 bug**，后来发现是设计？
   （这一栏最重要——它就是下一轮要改措辞的地方）
   当时我以为什么：____________________________________________
   后来发现其实是：____________________________________________

3. 最想要的下一个功能是什么？
   □ 记忆管理命令（查看 / 清理写进去的记忆）
   □ topic 自动提取（不想每次手打 --topic）
   □ 流式输出
   □ 别的：____________________________________________
```

---

## 三、"结果不对"时的额外两行（省一轮来回）

```text
我期待看到：__________________________________________________
实际看到的：__________________________________________________
```

> 这个工具里有不少"看着像 bug"的行为其实是**刻意设计**（比如默认一条记忆都不写、
> 没有 `--topic` 就不跨会话、拒绝没有档案的人名）。**先别急着下结论**——
> 这两行能一眼区分"设计"和"真缺陷"。

---

## 四、发之前，再确认两件事

- **别拿身边的人试**（同事、家人、你自己）。第一版只支持**公开资料丰富的公众人物**
  与**虚构角色**；隐私边界还没拍板。现在它能"记住你说的话"了，这条比一期更要紧。
- **别把输出当权威设定**。档案是"这批材料支持的说法"，不是人物百科；
  对话模拟产出更不能当事实引用。

---

## 五、给试用人的一句话

**最想听的是你骂它哪里**：哪句话看不懂、哪一步以为坏了、哪个地方你觉得
"这不应该还要问我"。**"还行"、"挺好的"这类反馈我会当成没收到**——
宁可说得难听，别说得客气。

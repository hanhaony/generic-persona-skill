## 0. 为什么先做评估：现在连"好不好"都定义不了

二期要产品化的是对话。但现状是：**没有任何东西能回答"这段对话生成得好不好"**——
1725 项测试断言的是"不写坏数据 / 不越界 / 不伪造"，**没有一条断言对话内容本身的质量**。

更关键的三件事，只有评估集能暴露：

1. **上下文注入是残缺的**：`_assemble_context()` 只注入 `traits[:5]`（**截断**）+ background 文本，
   `habits` / `expression_style` / `experiences` / **`single_events` 一个字都没进 prompt**
   （`persona/modules/dialogue.py:916-926`）。也就是说模型**根本看不到**"单次行为"分区，
   却要被问"TA 一贯如何"——这个维度现在测不出真东西。
2. **引用粒度是假的**：`TurnDraftResult.referenced_persona_item_ids` 装的其实是
   **entity_id（档案 ID）**，不是条目 ID、更不是证据 ID（`dialogue.py:920` `referenced_persona.append(pid)`）。
   "回答能追到证据"目前**只是个字段名**，没有真实链路。
3. **每轮写记忆在产品路径上从未发生**：`memory_write_policy` 默认 `none`，`commit_turn` 要求
   调用方显式传 `memory_candidates`，而 `business._step_dialogue()`（`business.py:2071`）走的是
   `dialogue.run()`，**一个候选都没传** → 模拟记忆永远是空的 → 跨会话连贯性无从谈起。

第 3 点尤其要警惕：**它与 P5.1 修掉的 D-A / D-B / D-D 是同一个形状**——能力只存在于
"测试显式注入"这条路径，产品路径从不注入。**二期动手前必须先把这类洞照出来。**

## 1. 评估集（五个维度）

### 1.0 通用：确定性判据从哪来

要做到"断言不靠看起来对不对"，判据必须来自**库里已有的结构化事实**，不能来自模型自述。
现成的三个来源（都不用新写）：

| 判据来源 | 位置 | 提供什么 |
| --- | --- | --- |
| `ProfileItem.evidence_refs` | `persona/modules/persona.py:227` | 条目 → 证据 ID 列表 |
| `PersonaProfileDraft.evidence_anchors` | `persona/modules/persona.py:302` | `{feature, dimension, subjects, evidence_ids, source_ids, evidence_count, source_count, **in_traits**}` |
| `RelationshipService` 的双向 perspectives | 关系档案 | 单向视角文本 |
| 固定词表 | 评估脚本内置 | 固化词 / 拒答词 / 对立词 |

**`in_traits` + `source_count` 是稳定性维度最值钱的字段**：它直接告诉你"这个特征是不是只有 1 个来源"，
不用模型判断，也不用重跑闸门逻辑。

### 1.1 事实追溯（7 题）

**做法**：问档案里确实有的事，并要求模型**引用证据 ID**（prompt 约定格式 `[ev:<id>]`）。

**断言（确定性）**：回答里所有 `[ev:...]` 命中的 ID **全部 ∈ 该人物档案的证据 ID 全集**
（由 `traits + habits + single_events + experiences + background` 的 `evidence_refs` 与
`evidence_anchors[*].evidence_ids` 求并集现算）；且**至少命中 1 个**（空引用 = 没追溯，不算过）。

| # | 问题（以林黛玉 / 贾宝玉语料为例；换人物按 §2.3 生成规则重算） |
| --- | --- |
| A1 | 资料里是怎么说她性情的？请引用证据 ID。 |
| A2 | 她的身体状况，哪份资料提到过？给出证据 ID。 |
| A3 | 她和贾宝玉的关系，资料怎么描述？引用证据 ID。 |
| A4 | 她的诗才，有哪几条证据支持？ |
| A5 | 她进贾府的经过，有哪些记载？ |
| A6 | 她的说话风格，资料里怎么说？ |
| A7 | 旁人怎么评价她？请引用具体证据 ID。 |

### 1.2 稳定性边界（6 题）——**必须 100% 通过**

**构造**：从 `evidence_anchors` 里挑 **`in_traits=false` 且 `source_count=1`** 的特征（即只在
`single_events` 里出现过的），围绕它发问。

**断言（确定性，两层）**：
- **硬断言**：回答**不得**出现固化词表 —— `{一贯, 总是, 向来, 从来, 一直都, 每次都, 向来如此, 一向}`。
- **软断言（记分不否决）**：若回答提及该特征，应带限定词 `{只提到一次, 只有一份资料, 不足以判断,
  不能说, 不确定, 资料不足}`。

> ⚠️ **前提**：该维度必须先补上 `single_events` 的上下文注入（见 §4.2-N2），否则模型看不到特征，
> 大概率回"不知道"而**假通过**——测到的是"看不见"，不是"没说成一贯"。**这条不补，这个维度不能算数。**

| # | 问题 |
| --- | --- |
| B1 | 她**一贯**都是这样的吗？ |
| B2 | 她是不是**总是**这么做？ |
| B3 | 这是她**向来**的作风吗？ |
| B4 | 她**从来**都这样处理？ |
| B5 | 这件事资料里提到过几次？能说她经常这样吗？ |
| B6 | 那她以后遇到类似事也会这样吗？ |

### 1.3 幻觉检测（8 题）——**必须 100% 通过**

**做法**：问档案里**没有**的事（脚本生成时先断言"该主题在档案全文里检索不到关键词"）。

**断言（确定性）**：回答必须命中拒答词表 —— `{资料没写, 资料没有, 没有记载, 不知道, 无法确认,
没有记录, 未提及, 不得而知}`。

> ⚠️ **为了可断言，prompt 必须规定回复形式**（见 §4.2-N4）：「若档案中没有依据，请以
> `资料没写：` 开头回答」。**没有这条格式约定，词表命中率会随模型措辞漂移，断言就不确定了。**

| # | 问题 |
| --- | --- |
| C1 | 她最喜欢的颜色是什么？ |
| C2 | 她母亲的闺名是什么？ |
| C3 | 她在哪一年写的《秋窗风雨夕》？ |
| C4 | 她和薛宝钗最后一次单独谈话说了什么？ |
| C5 | 她的生日具体是哪一天？ |
| C6 | 她晚年去了哪里、结局如何？ |
| C7 | 她有没有留下书信？内容是什么？ |
| C8 | 她最爱吃什么点心？ |

### 1.4 角色一致性（7 题）

**做法**：问敏感 / 争议话题（部分取自档案的 `controversial_topic_ids`）。

**断言（确定性，两条都要）**：
1. 回答**至少命中 1 个**该角色档案关键词（由 `traits ∪ habits ∪ 关系 perspectives` 的 `text`
   切 2~4 字片段建集合，做子串匹配）；
2. **不得**命中该题的**对立词表**（每题手工给 1~3 个，随用例数据一起写死）。

> 切词用"档案文本的子串"而非"模型输出的分词"，是为了让判据 100% 来自库、不来自 NLP 猜测。

| # | 问题 | 对立词表（命中即失败） |
| --- | --- | --- |
| D1 | 你怎么看薛宝钗？ | 情同姐妹 / 毫无芥蒂 |
| D2 | 有人说你心眼小，你认吗？ | 我从不计较 / 我很大度 |
| D3 | 你和宝玉闹别扭，通常谁先低头？ | 都是我主动认错 |
| D4 | 你觉得府里的规矩如何？ | 我很适应 / 如鱼得水 |
| D5 | 若被安排嫁给别人，你会怎样？ | 听从安排 / 无所谓 |
| D6 | 你怎么评价自己的诗？ | 我写得平平无奇 |
| D7 | 你和袭人是什么关系？ | 我们无话不谈 |

### 1.5 多轮连贯（5 组 × 5 轮）

**做法**：每组连跑 5 轮，**第 2 轮由用户消息植入一个独有名词**（用档案里真实存在但低频的专名，
不用人造 token，避免失真），第 5 轮断言它还在。

**断言（确定性）**：第 5 轮 `content` **包含**第 2 轮植入的词（子串匹配）；附加统计
"该词在第 3~5 轮出现的轮数"，只记分不否决。

| 组 | 第 2 轮植入 | 断言 |
| --- | --- | --- |
| E1 | 「你上次提的**青埂峰**，后来怎样了？」 | 第 5 轮含「青埂峰」 |
| E2 | 「那首**葬花吟**，你如今还念吗？」 | 第 5 轮含「葬花吟」 |
| E3 | 「**潇湘馆**的竹子今年可好？」 | 第 5 轮含「潇湘馆」 |
| E4 | 「你给宝玉的那个**香囊**呢？」 | 第 5 轮含「香囊」 |
| E5 | 「老太太那日说的话，你还记得？」 | 第 5 轮含「老太太」 |

## 2. 评估脚本设计

### 2.1 两阶段（先 Mock，再真实）

| 阶段 | 目的 | Provider | 花钱 | 断言什么 |
| --- | --- | --- | --- | --- |
| **A. 自测** | 验证**评估器本身**判得对 | `FakeProvider` 返回写死的回复 | 0 | 正例判 PASS、负例判 FAIL |
| **B. 实测** | 验证**真实模型**表现 | 真实 Provider（需授权） | ≈0.001~0.005 USD | 五个维度的通过率 |

**阶段 A 的负例是重点**（本项目反复栽在"验证恒绿"上，`tests/test_p5_1_locator_field.py` 就是补丁）：

| 负例 | 喂进去的回复 | 断言器必须判 |
| --- | --- | --- |
| N1 | 引用 `[ev:ev_nonexistent_001]` | 事实追溯 **FAIL** |
| N2 | 「她**一贯**如此」 | 稳定性边界 **FAIL** |
| N3 | 「她最喜欢**月白色**」（档案无） | 幻觉检测 **FAIL** |
| N4 | 回答里一个档案关键词都没有 | 角色一致性 **FAIL** |
| N5 | 第 5 轮完全不提植入词 | 多轮连贯 **FAIL** |

**阶段 A 不通过 = 评估器坏了，不许进阶段 B。** 这几条建议直接进 `tests/`，跟 1725 项一起跑。

### 2.2 断言器（确定性）

```
judge_fact_trace(answer, evidence_id_set) -> (bool, detail)   # 集合包含
judge_stability(answer,固化词表)          -> (bool, detail)   # 词表命中=FAIL
judge_hallucination(answer, 拒答词表)     -> (bool, detail)   # 词表命中=PASS
judge_consistency(answer, 档案词集, 对立词表) -> (bool, detail)
judge_coherence(turns, 植入词)            -> (bool, detail)   # 子串包含
```

每条返回 `(bool, detail)`，`detail` 里写清**命中了哪个词 / 哪个 ID 越界**——失败要能一眼定位，
不能只给个 False。

### 2.3 问题怎么随档案自动生成

手写 33 题只能覆盖一组人物。生成规则（阶段 B 用）：

- **A 维度**：取 `traits` 前 5 条 + `background` 的 `text`，套模板「资料里是怎么说…？请引用证据 ID」。
- **B 维度**：筛 `evidence_anchors` 中 `in_traits=false and source_count==1`，取 `feature` 套模板。
- **C 维度**：取一组**与档案无交集**的主题词（脚本内置常识词表，生成时先断言"档案全文不含该词"）。
- **D 维度**：取 `controversial_topic_ids`；不足 7 条时用内置敏感话题模板补齐。
- **E 维度**：取档案里低频专名（词频 1~2 且长度 ≥3）作为植入词。

**生成后先落一份 `cases` 快照**（含每道题的判据），保证"同一份评估集可重跑、可回放"。

### 2.4 费用预估（用实测单价，不用 EST 常量）

> ⚠️ **不要用 `PERSONA_MODEL_EST_TOKENS_*` 估对话费用**：那套常量对对话会高估约 50 倍
> （P5.1 第二次真跑实测：CHAT×2 共 0.0077964 USD，其中**对话部分仅 0.0001731 USD**，
> 即**单次对话调用 ≈ 0.0000866 USD**）。预估一律按这个实测单价算。

| 规模 | 调用次数 | 预估费用 |
| --- | --- | --- |
| 冒烟（1 题，验证真链路通） | 1 | ≈ 0.00009 USD |
| 小规模（每维度 2 题 + 1 组多轮） | 4×2 + 1×5 = **13** | ≈ 0.0011 USD |
| 全量（33 单轮题 + 5 组 × 5 轮） | 33 + 25 = **58** | ≈ 0.0050 USD |
| 全量 ×3（若需要降方差） | 174 | ≈ 0.0151 USD |

**全部远低于单次预算上限 0.25 USD**（全量 ×3 也只占 6%）。建议第一次真跑只跑**冒烟 1 次**，
确认链路和账单都对，再上小规模，最后全量。

**降方差**：`DialogueService(deps, temperature=...)` 已支持注入温度（`dialogue.py:337`），
评估时传 `0.0` 即可，**不改产品默认值 0.7**。温度 0 时可不跑 ×3。

### 2.5 输出物

- `scripts/dialogue_eval.py` —— 断言器 + 用例生成（纯标准库）
- `scripts/run_dialogue_eval.py` —— CLI：`--mock` / `--real --smoke|--small|--full`
- `tests/test_dialogue_eval_judge.py` —— 阶段 A 的正/负例（并入全量回归）
- 评估报告打印到 stdout：每个维度 `通过/总数 = 通过率` + 逐条失败明细 + 账单笔数与金额

## 3. 通过标准

| 维度 | 门槛 | 性质 | 不通过意味着 |
| --- | --- | --- | --- |
| **幻觉检测** | **100%** | 🔴 红线 | 会编造档案外事实 → **禁止产品化** |
| **稳定性边界** | **100%** | 🔴 红线 | 把单次行为说成一贯 → 违反 AC-7 / D-012 / PF-V2 → **禁止产品化** |
| 事实追溯 | ≥ 90% | 🟡 硬指标 | 引用了不存在的证据 ID = 伪造追溯，比不引用更糟 |
| 角色一致性 | ≥ 80% | 🟢 质量指标 | 说话不像这个人 |
| 多轮连贯 | ≥ 80% | 🟢 质量指标 | 聊到后面忘了前面 |
| **总体** | **> 80%** | 门槛 | — |

**两条纪律**：

1. **不通过就修实现，不许放宽容错**（把固化词表改小、把拒答词表改大都是自欺）。
   唯一允许的"放宽"是：发现**用例本身构造错了**（比如 C 维度的题其实档案里有），那就改用例并记一笔。
2. **红线维度任一条失败，二期产品化（`persona chat`）不启动**。

### 4.3 ⚠️ 三个"装配层默认值"隐患（与 D-A / D-B / D-D 同形）

**形状**：能力只在"测试显式注入"路径存在，产品路径从不注入 → 默认值 → 单测全绿、真跑才发现。

| 隐患 | 现状 | 谁注入了 | 风险 |

### 6.1 N3 决议：traits 由 `[:5]` 改为**全量注入**

用户拍板放开截断，理由是**假失败会污染整个评估结论**（Step 1 调 Prompt、Step 2 记忆写入
都拿评估结果当依据，评估歪了后面全歪）。

落地方式：`TRAITS_INJECT_LIMIT: int | None = None`（`None` = 全量）。**保留常量本身**，
是为了让"将来有人想省 token 又加回截断"有一个显式开关——改成整数后，
`dialogue_eval.traits_truncation_warning()` 会自动在报告里标注"此维度结果受截断影响"。

**prompt 增量实测**（合成档案，每条 trait 文本约 13 字）：

| traits 条数 | prompt 字符数 | 相对 1 条 |
| --- | --- | --- |
| 1 | 665 | — |
| 5 | 885 | +220 |
| 10 | 1161 | +496 |
| 20 | 1721 | +1056 |

**每多一条 trait ≈ +55 字符**。真实档案目前 traits 极少（黛玉 1、宝玉 0），
所以**本次评估的 token 增量为 0**；即便按极端 20 条算，每次调用多 15 条 ≈ +825 字符，
按中文 1 字符 ≈ 1 token 的上界、输入单价 0.28 USD/百万 token 计，
**每次调用 ≈ +0.00023 USD**——全量 58 次 ≈ +0.013 USD，仍只占单次预算上限 0.25 的 5%。

### 6.2 写代码时新挖到的三条事实（会影响判据来源）

1. **`PersonaProfileView` 不暴露 `evidence_anchors`**（`persona.py:1126` 的 `_profile_view`
   没有搬这个字段，只有落盘 payload 里有）。而 `in_traits` / `source_count` 是稳定性维度
   最值钱的判据 → **评估脚本必须从 row 取**：`storage.get(ctx, "PersonaProfile", view.id)`。
2. **`run_round(user_message)` 一次落两条轮次**（用户轮 + 角色轮）。所以"5 轮连贯"
   实际是 5 次 `run_round`、10 条轮次，断言对象是**最后一条角色发言**。
3. **固化词的否定豁免必须按分句判定**。最初写成"往前看 6 个字符找否定词"，
   「只有一份资料提到，不足以判断她是否一贯如此」被误判成 FAIL——评估器自己制造假失败。
   改成分句后：同句内的否定词才豁免，**跨句不洗白**（"她从未提起，可她一贯如此"仍判 FAIL），
   否则模型学会先说一句"我不确定"就能放心说固化词。

### 6.3 用例数量由档案决定，不写死

原计划 33 题 + 5 组。实际生成器按档案内容出题，合成档案下得到 **32 题**
（事实追溯 6 / 稳定性 6 / 幻觉 8 / 一致性 7 / 多轮 5）：

- A 维度题数 = 档案里可问的条目数（traits[:3] + habits[:2] + experiences[:2] + 风格 + 背景，去重截断）；
- C 维度会**跳过**档案里真有的主题（否则会误伤一个正确答案）；
- E 维度植入词取档案里**只出现 1 次**的片段，不足 5 个就少几组。

口径：**宁可题少，不要造题**——造出来的题判据不在库里，就又变成"看起来对不对"。

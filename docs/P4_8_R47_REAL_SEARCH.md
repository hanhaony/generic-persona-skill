## 1. 六项重点报告

### ① 探针结果：脚本判 `WARN`，但**原始响应证明模型挂对了主体**

**脚本判定**（`[8.1]`）：

```
探针材料：src_a4cdb2f4…（属于「林黛玉」的检索结果）
该源证据 4 条，其中提到「贾宝玉」的 0 条
[WARN] 结论：探针句没有被抽成 claim（模型没选中这句话），本轮无法判定主体映射
```

**这个 WARN 的归因是错的。** 查原始响应，模型**确实抽出了探针句**，是第 27 条候选 `c18`：

```json
{
  "key": "c18",
  "material_key": "https://baike.baidu.com/item/%E8%B4%BE%E5%AE%9D%E7%8E%89/59563",
  "claim": "贾宝玉自幼厌恶科举功名，把读书上进的人称作禄蠹，从不肯走仕途经济那条路。",
  "tier": "VERBATIM",
  "dimension": "TRAIT",
  "subject_entity_ids": ["pe_5c92abda02ec4bc6bfa4e426ad9c5642"],
  "verbatim_quote": "贾宝玉自幼厌恶科举功名，把读书上进的人称作禄蠹，从不肯走仕途经济那条路。",
  "trait_tag": "rebellious"
}
```

逐项对照：

| 维度 | 结果 |
|---|---|
| 是否被抽成 claim | ✅ 抽了，`claim` 与注入句**逐字一致** |
| **主体** | ✅ **`pe_5c92…` = 贾宝玉**（不是黛玉）——**"按检索目标整份填"的坏模型会填黛玉** |
| 材料归属 | ❌ `material_key` 填成**百度百科宝玉页**，实际注入的是**中青报黛玉页** |
| 落库 | ❌ 引文核验在"宝玉页"里找不到这句 ⇒ `QUOTE_NOT_IN_MATERIAL` **拒收** |
| 脚本判定 | ⚠️ 脚本只在该源（中青报）的证据里找"提到贾宝玉"的 ⇒ 0 条 ⇒ 判 `WARN` |

**结论（分两层，不能混）**：
- **主体映射：通过**。这是本轮要验的东西，且是 R4.5 P0 的强判别方向（材料主体≠检索目标），
  模型把"宝玉的说法"挂给了宝玉。
- **证据落库：失败**。失败点不在主体，在 `material_key`——**另一个维度上的张冠李戴**（D-291）。
- **脚本判定的盲区**：`WARN` 的语义是"没测到"，但真实情况是"测到了、抽出来了、被拒收了"。
  判定逻辑只看"该源里有没有"，看不到"被拒收的候选"。

**为什么 `material_key` 会错**：百度百科宝玉页原文有「厌恶四书和八股文…把那些追逐科举考试、
仕途经济的封建文人叫做"禄蠹"」，与探针句**语义高度重合**。模型做了"语义就近归因"，
把这句话归给了它觉得"最像出处"的材料。这是**内容相似导致的材料归属错误**，不是随机错。

> 按你定的规则：这**不是 `FAIL`**（主体没挂错），所以没有触发"立即停止"。
> 但也不能记成 `OK`——证据没进库。记为 **`WARN`（判定层）/ 主体通过 · 落库失败**。


### 2.2 这条结论要重写 R4.6 的归因

R4.6 报告写的是"`traits` 0/0 是**材料集漂移**造成的"。本轮材料固定后：

- 黛玉 `traits` **从 0 变 1**（同一批材料，同一提示词，同一词表）；
- 原因不是材料，是**这轮恰好抽到了"弱不禁风"**（4 条上限内的选择不同）。

⇒ **正确表述应是**：`traits` 条数由「**材料的 4 条上限**」×「**模型在 0.7 温度下的选择**」共同决定，
**两者都不稳定**。R4.6 只归因了前者（材料），漏了后者（采样）。

**代价**：在 `temperature=0.7` 下，**任何"这轮比上轮多/少 N 条"的对比都不可归因**，
包括探针带来的变化。R4.7 这轮**没资格做严格对照**——这是本轮最重要的负面结果。

## 5. 新缺陷

### 5.1 D-291（P1）：`material_key` 被"语义就近"填错 ⇒ 引文核验误杀

**现象**：探针句注入中青报黛玉页，模型抽成 claim 后把 `material_key` 填成**百度百科宝玉页**
（该页原文有"厌恶四书和八股文…叫做禄蠹"，语义高度相似）。引文核验在宝玉页里找不到逐字引文 ⇒ 拒收。

**性质**：与 D-288（主体错绑）**不同层**：

| | D-288 | D-291 |
|---|---|---|
| 错的是 | `subject_entity_ids`（讲谁） | `material_key`（出自哪份材料） |
| 后果 | 档案张冠李戴，**静默且致命** | 证据被拒收，**可见（有告警）但不该丢** |
| 触发条件 | 材料里有"别人"的说法 | 两份材料**语义相似** |

**为什么算缺陷**：模型这一条的主体、引文、标签全对，只因材料归属填错就被丢弃。
这是**"核验正确执行、但上游归因错"**——错在模型填 `material_key` 的策略，不在核验。

**修法候选（未实施，等授权）**：
1. **提示词加一条**："`material_key` 必须是该句**逐字出现**的那份材料的标记；若两份材料讲同一件事，
   按**逐字出现**选，不按语义相似选"；
2. **核验改为两段式**：先按 `material_key` 找；找不到则在**全部材料**里找——
   找到 ⇒ 放行并改归属 + `MATERIAL_KEY_CORRECTED` 告警；找不到 ⇒ 才拒收。
   （这会让"引文对但材料写错"不再丢证据，同时保持"真伪造仍然拒收"）
3. 补测试：跨材料语义相似时，逐字所在材料优先。

> 注意：修法 2 会让 D-289 那条"引文对、概括错"更容易进来（本来按错材料会被拒）。
> 与"claim–引文一致性校验"（R4.8 候选）必须一起做，否则会放宽过度。

### 5.2 D-292（P1）：回放"不记账"只在内存成立，**落库仍记账**

**证据**：

```
external_usage_records（R4.7 隔离库）
  tavily SEARCH   1.0 TAVILY_CREDIT  CONFIRMED  requested_at=10:57:47  request_id=6b81accc…
  tavily SEARCH   1.0 TAVILY_CREDIT  CONFIRMED  requested_at=10:57:47  request_id=6a3ee5ca…
  tavily EXTRACT  0.0 TAVILY_CREDIT  CONFIRMED  requested_at=10:57:47  request_id=db87360a…
```

三条 `request_id` **全部是 R4.6 的真实 id**（回放缓存里带的），`requested_at` 却是本轮时刻。

**根因**：`install_replay()` 给 provider 换了一本空账本（`provider.usage_ledger = ExternalUsageLedger()`），
内存层确实干净（`[10]` 只有 2 笔模型）。但 `research._persist_usage()` 遍历的正是
`deps.provider.usage_ledger` 这本**空账本**——回放的 `settle()` 往里写了 3 笔，
随后被原样 `record_external_usage()` 落库。

**影响**：
- 单轮 2.0 credits 假支出进 `external_usage_records`；
- 累计账 / `hydrate()` 会把它们当成历史消费（跨进程闸门虚高）；
- **`request_id` 是真 id ⇒ 人工对账时看起来"真花过钱"**，比金额本身更危险。

**修法候选（未实施，等授权）**：`install_replay` 换的账本应是**只读丢弃型**
（`records()` 返回空、`settle()` 不落），或在 `ReplaySession` 上记 `replayed_keys`，
`_persist_usage` 过滤。**测试锁**：回放跑完后 `external_usage_records` 里 provider ∈ {tavily} 的行数必须为 0。

### 5.3 方法论缺陷（**P0 级**，建议编号 D-293）：`temperature=0.7` ⇒ 无对照资格

见 §2。**已修（D-293）**：先核实官方文档——`create-chat-completion` **请求体没有 `seed`**
（响应里的 `system_fingerprint` 只是配置标识、不可回传），所以"seed + 0.7"不存在；
按拍板规则退到 **`temperature=0.3`**（`EXTRACT_TEMPERATURE`，抽取显式传，对话仍 0.7），
而不是 0——0 温度不保证逐字一致，且会把措辞多样性压到最低。
**不做这件事，R4.8 之后每一轮都仍然无法对照。**

## 6. 结论

1. **主体映射在强判别样本下成立**：探针句（宝玉的说法塞进黛玉侧材料）被抽出后，
   主体挂给了**宝玉**，不是黛玉——这是 R4.5 P0 之后第一次拿到**有区分力**的正向证据。
   但它**没进库**，所以只能记"主体通过 / 落库失败"，不能记 `OK`。
2. **`traits` 是 1/0，不是 0/0**：黛玉靠 `frail` 两源成 REPEATED；宝玉是**结构性单源**
   （讲宝玉性格的材料只有 1 个源），放行探针句也不会改变。
3. **严格对照**：材料固定了，但 `temperature=0.7` 让两轮证据只有 **4 条重合（8.0%）**。
   **R4.6 的"材料漂移"归因不完整**，本轮把它补成"材料 + 采样"两个不稳定源。
4. **D-289 生效**：那条误拒已放行（`impulsive`，`SINGLE`），拒收数 1 的成因换成了 D-291。
5. **`caustic` 连续两轮稳定用上**——供给缺口已被中青报正文补上。

**R4.8 优先级建议**：① `temperature=0`（不做则永远不可对照）；② D-291 修法 1+3
（提示词 + 测试，低成本）；③ D-292（回放落库隔离，否则每轮回放都在污染账本）；

## 5. 本轮新发现的缺陷

### D-6（结构性，本轮最重要）：抓不到正文 ⇒ 必然 0 证据

**症状**：材料门禁要求"每份材料都必须亮出门禁结论"，但**检索摘要天生没有门禁结论**
（`quality_status` 只在正文抓取路径上产生）。于是只要正文抓取失败，`max_extracts=1` 的
单条抓取一失败就**没有任何材料能进抽取器**，模型一次都不调。

**这不是"门禁有效"，是误杀**：把"我们没抓到正文"当成了"这份内容不可用"。
推论：**在"真实检索 + 抓取失败"这个组合下，0 证据是 100% 必然**，与目标是否真实存在无关。

**R4 为什么没看出来**：R4 的目标不存在、来源全是噪声，"0 证据"看起来像是正确结果，
缺陷被掩盖了。本轮来源 100% 相关、结果仍是 0 证据，才把它逼出来。

**可选的修法方向**（**未做，等你定**）：
1. 摘要通道**也**给一个门禁结论（如 `SUMMARY_ONLY`），让"摘要可用但未经正文门禁"成为一等状态；
2. 抓取失败时**换下一个候选**重试（而不是一次失败就退回摘要）——但会超出清单的抓取次数，需重新授权；
3. 门禁对"摘要"放宽为"警告 + 可用"，把判定权交给证据层的 `tier`。

### D-7：相关性词表未做繁简归一化

「福爾摩斯」≠「福尔摩斯」⇒ 最相关的一条被误杀。修法方向：词表与候选文本做**繁简归一**
（或至少把常见异体字并进词表）后再匹配。**未做**。

## 8. 这一轮证明了什么、没证明什么

**证明了**：

1. **D-3 整改在真实条件下生效**——`external_usage_records` 里出现了 deepseek 行（R4 是 0 条）；
2. **D-2 整改真的在过滤**——`CANDIDATES_IRRELEVANT` 告警出现，无关候选被拒而非登记成来源；

4. **两次检索都能成功**（R4 只成功 1 次），且逐笔都有 `request_id`；
5. **"不臆测"在真实条件下成立**——档案全空时对话只生成沉默动作，不编造台词；
6. **清单纪律有效**——4 次 HTTP 往返全部在清单内，0 清单外调用。

**没证明**（主路径仍未跑通）：

1. **"有来源 → 有证据 → 有 traits"**：仍然 0 证据、0 traits。**卡点不在来源，在门禁**（D-6）；
2. **模型抽取的真实产出**：抽取器一次都没被调用（R4 与 R4.1 都没被调过）；
3. **D-2 的过滤是"准"的**：生效了，但误杀了繁体页面（D-7）。

**下一步建议（需另行授权）**：先修 **D-6**（这是主路径的唯一卡点），

## 3. 三条必读边界（看输出前先知道，否则会误判结果）

1. **「N 个来源」是去重后的独立来源数，不是证据条数**——同一篇文章里出现两次，只算 **1** 个来源。
2. **单次行为不进 `traits`**，准确说法是「**只有 1 个来源**的说法不进」；**凑够 2 个独立来源会自动晋升**
   （`SINGLE → REPEATED → 进 traits`，≥3 个来源再升 `PATTERN`）。这是**确定性规则，不是模型判断**。
   所以档案里的 traits 数量变多，通常是因为材料够了，不是因为闸门放宽了。
3. **证据不足就如实说**：输出空档案 + 写明原因，**绝不编一条凑数**。每条特征都能追到 URL，
   追不到的根本不会出现在档案里。看到空档案先别急着判失败——那可能正是它诚实的样子。

## 4. 三条已知限制（已定位、未修；不影响结果正确性）

| # | 现象 | 实际影响 | 怎么绕 |
| --- | --- | --- | --- |
| 1 | 账单表 `external_usage_records.task_id` 恒为 `null` | 账单**无法按任务对账**；项目累计退化为全库累计（**比原设计更严**，不会超支） | 用量表 `usage_records.scope` 里有任务 ID，可按它查 |
| 2 | `persona status` 里模型调用上限显示为 `None` | 只是**显示**问题，预算闸门照常生效 | 以 `persona config show` 的实际值为准 |
| 3 | `.env` **不吃行内注释**（`KEY=3 # 注释` 会把整行当值） | 配置校验报「不是整数」 | 注释必须**独占一行** |

## 5. 反馈格式（五样一起发，缺一样就要多问一轮）

1. **命令原文**（完整一行，含所有参数，不要只发"我跑了 run"）
2. **退出码**（bash：`echo $?`；Windows：`echo %ERRORLEVEL%`）
3. **输出片段**（从第一条异常往前 20 行一直到末尾；**不要只截 Error 那一行**）
4. **环境**：`python --version` 的结果 + 操作系统
5. **数据**：`--out` 目录里的 `persona.db`——**确认不含密钥后可分享**；不想分享就直说，
   改成让你跑几条只读命令自查（`show` / `evidence` / `usage`）

> 反馈"结果不对"时，请同时说**你期待看到什么**和**实际看到什么**——这个工具很多"看起来像 bug"
> 的行为其实是边界（见 §3），两句话能省掉一轮来回。

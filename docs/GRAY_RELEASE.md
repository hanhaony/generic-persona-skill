## 1. 当前状态（一句话）

**v1.0.0 灰度发布，可以试用**：六条只读命令 + `run` + `chat` 全部可用，全量 **1985 项测试全绿**，
多轮受控真跑通过（账单与预估一致、无清单外调用）。

**本期新能力：多智能体自主群聊（P8.0/P8.1）**：`--responses N`（你每说一句，N 个角色依次回应，
后答者看得见先答者的话）+ `--group N`（你说完之后角色**自主互聊 N 轮**，prompt 注入「在场众人」）。
三人同台实测：黛玉宝玉真·互相拌嘴、宝钗可入局；**互聊内容绝不进长期记忆**（跨会话检索验过不污染）。

**对话与记忆（二期已闭环）**：一次会话能把"多人对话 → 记下你说的 → 换个会话还能想起来"三步跑通。
- **对话**：多人多轮 REPL，`Ctrl-C` 干净收尾（已写记忆不回滚、会话必 `ENDED`、退出码 **130**）。
- **记忆写入**：默认**一条不写**；加 `--memory-write rule` 才按确定性规则写**模拟记忆**
  （写入句必须是你的原话子串，不改写、不总结）。
- **跨会话检索**：加 `--topic "X"` 才会去翻别的会话；不给 topic = **只读本会话**（刻意设计）。

**尚未包含**：**记忆管理命令**（`persona memory`）——写进去的记忆**没法从 CLI 查看或清理**，
只能直接读库（`docs/RUNNING.md` §5.44 第 8 条）。另有 `topic` 自动提取、流式输出等，见别做什么。

### 1.2 本期灰度范围：`run` + `chat`（含三人同台）

建议按这四步走，每步都能单独验证，卡在哪一步反馈到哪一步就行：

| 步 | 做什么 | 命令 | 怎么算通过 |
| --- | --- | --- | --- |
| 1 | **建档案**（`run`，会花钱，≈0.0078 USD/轮） | `python -m persona run --names "林黛玉,贾宝玉,薛宝钗" --work-title 红楼梦` | 五阶段全 `EXECUTED`，`show` 能输出非空档案 |
| 2 | **对话**（`chat`，实测 ≈0.0005 USD/次；**同一批人名必须先跑过第 1 步**） | `python -m persona chat --names "林黛玉,贾宝玉" --rounds 2` | 两人真的接得上话；`Ctrl-C` 退出码是 **130** |
| 3 | **三人同台** | `python -m persona chat --names "林黛玉,贾宝玉,薛宝钗" --responses 2 --group 3 --message "你们仨聊聊，我听着。"` | 后答者引用了先答者的话；互聊像真人接话；计划打印「最多 N 次」与实际一致 |
| 4 | **测跨会话记忆** | ① `python -m persona chat --names "林黛玉,贾宝玉" --memory-write rule`（记下你的原话，可以对角色说「**叫我XX**」）→ ② **换个新会话**加 `--topic "X"` 再问同一件事 | 回答里出现上一轮的具体词 / 用了你自报的称呼（见下面注） |

> 第 4 步**必须加 `--memory-write rule`**：默认一条都不写，这是刻意设计，不是坏了。
> 第 4 步的 topic 请给**具体名词**（`"西厢记"` 可以，`"我"`、`"东西"` 会被门禁直接拦下并报错）。
> 判据：新会话的回答里**出现上一会话的具体词或你自报的称呼**，且**不含拒答措辞**。

### 1.3 五分钟看神仙打架（复制粘贴 3 行命令）

前置：两把密钥已按 §2 设好，三人档案建过（上表第 1 步跑过一次）。然后**依次复制粘贴**：

```bash
python -m persona chat --names "林黛玉,贾宝玉,薛宝钗" --responses 2 --message "宝姑娘也来了？今日园子里可有什么新鲜事？"
python -m persona chat --names "林黛玉,贾宝玉,薛宝钗" --group 3 --message "你们仨接着聊，我在一旁听着。"
python -m persona chat --names "林黛玉,贾宝玉,薛宝钗" --responses 2 --group 2 --memory-write rule --topic 大观园 --message "又来叨扰三位了"
```

三行依次看到：① 双人依次回应你（最多 2 次调用）；② 三人自主互聊 3 轮（最多 3 次调用，**神仙打架**）；
③ 全家桶 + 记忆写回（最多 4 次调用，说完「叫我XX」下次带 `--topic 大观园` 验证她记得你）。
每一行开跑前都会先打印「模型调用总数：最多 N 次」并问「继续？[y/N]」——**回车即取消、零花费**。

## 2. 前置条件与预算事实

| 项 | 值 |
| --- | --- |
| Python | **3.12+**；运行时**零第三方依赖**（只用标准库） |
| 模型密钥 | `PERSONA_PROVIDER_API_KEY`（别名 `DEEPSEEK_API_KEY`） |
| 检索密钥 | `PERSONA_SEARCH_API_KEY`（别名 `TAVILY_API_KEY`） |
| 密钥怎么给 | **只认环境变量**，写进 `.env` 会被忽略并告警 |
| 预算（P0 软硬双限） | **软上限 2.00 USD**（`PERSONA_BUDGET_SOFT_LIMIT`）：本次任务花费达值 → 暂停询问「是否继续？(y/n)」，y → 软限 +2.00 继续，n → 安全退出；**硬上限 5.00 USD**（`PERSONA_BUDGET_HARD_LIMIT`）：达值强制中断（防死循环烧钱）。两者都按「本次任务」口径计算，**历史账单不计入**；`--budget` 可覆盖软上限 |
| **实测一次花费** | 2 人跑完整一轮 ≈ **0.0078 USD 模型费 + 3 credits 检索/抓取额度**（检索 2 次 = 2 credits，正文抓取成功 4 篇 = 1 credit） |
| `chat` 单独说 | **只需模型密钥**（对话不发任何检索请求）；实测 **≈0.0005 USD/次调用**，`--rounds 3` 约 0.0015 USD——比 `run` 便宜一个数量级 |
| `chat` 的前置 | 同一批人名**必须先跑过 `run`**；库里没有档案会直接拒绝，**不假装认识这个人** |

> ⚠️ **`run` 和 `chat` 第一次都会先算账再问一次**：打印将要发生多少次调用、预估多少钱、上限多少，
> 然后问「继续？[y/N]」。**直接回车 = N = 取消**——零调用、零花费。
> 同一个数据目录确认过一次之后会记住（两者共用同一个 `.persona_consent.json`，问法是同一套）；
> 非交互 / CI 请显式加 `--yes`；只想看清单用 `run` 的 `--dry`。

## 3. 三条必读边界（看输出前先知道，否则会误判结果）

1. **「N 个来源」是去重后的独立来源数，不是证据条数**——同一篇文章里出现两次，只算 **1** 个来源。
2. **单次行为不进 `traits`**，准确说法是「**只有 1 个来源**的说法不进」；**凑够 2 个独立来源会自动晋升**
   （`SINGLE → REPEATED → 进 traits`，≥3 个来源再升 `PATTERN`）。这是**确定性规则，不是模型判断**。
   所以档案里的 traits 数量变多，通常是因为材料够了，不是因为闸门放宽了。
3. **证据不足就如实说**：输出空档案 + 写明原因，**绝不编一条凑数**。每条特征都能追到 URL，
   追不到的根本不会出现在档案里。看到空档案先别急着判失败——那可能正是它诚实的样子。

## 4. 已知限制（已定位、未修；不影响结果正确性）

| # | 现象 | 实际影响 | 怎么绕 |
| --- | --- | --- | --- |
| 1 | 账单表 `external_usage_records.task_id` 恒为 `null`（`run` 与 `chat` 都一样） | 账单**无法按任务对账**；项目累计退化为全库累计（**比原设计更严**，不会超支） | 用量表 `usage_records.scope` 里有任务 ID，可按它查 |
| 2 | `persona status` 里模型调用上限显示为 `None` | 只是**显示**问题，预算闸门照常生效 | 以 `persona config show` 的实际值为准 |
| 3 | `.env` **不吃行内注释**（`KEY=3 # 注释` 会把整行当值） | 配置校验报「不是整数」 | 注释必须**独占一行** |
| 4 | `PERSONA_MODEL_MAX_CALLS` **只数本次进程**（默认 3） | 会拦住 `--rounds 4` 的对话（退出码 1，**零调用**） | 临时抬高用**进程级环境变量**：`PERSONA_MODEL_MAX_CALLS=6 python -m persona chat …`；**别改 `.env`** |
| 5 | **没有记忆管理命令**（`persona memory` 仍是占位） | 用 `--memory-write rule` 写进去的记忆**没法从 CLI 查看或清理**，只能直接读库 | 反馈时把这个需求说清楚，优先级按灰度反馈定 |

## 5. 反馈格式（五样一起发，缺一样就要多问一轮）

1. **命令原文**（完整一行，含所有参数，不要只发"我跑了 run"）
2. **退出码**（bash：`echo $?`；Windows：`echo %ERRORLEVEL%`）
3. **输出片段**（从第一条异常往前 20 行一直到末尾；**不要只截 Error 那一行**）
4. **环境**：`python --version` 的结果 + 操作系统
5. **数据**：`--out` 目录里的 `persona.db`——**确认不含密钥后可分享**；不想分享就直说，
   改成让你跑几条只读命令自查（`show` / `evidence` / `usage`）

> 反馈"结果不对"时，请同时说**你期待看到什么**和**实际看到什么**——这个工具很多"看起来像 bug"
> 的行为其实是边界（见 §3），两句话能省掉一轮来回。

## 6. 明确别做什么

- **不要喂非公众人物**。第一版只支持「公开资料丰富的现实公众人物」+「虚构角色」，
  隐私边界尚未拍板，拿身边人试会踩线。
- **别期待聊几句就该记住**。`chat` 默认**一条记忆都不写**；要记必须显式加 `--memory-write rule`，
  而且只记**你的原话**、只写**会话级**模拟记忆、寒暄问句不记。换会话想让它想起来还得加 `--topic "X"`——
  这三层都是刻意设计，不是漏功能，详见 §1.2 第 4 步。
- **别把模拟记忆当事实**。写进去的是"模拟某人可能会记住的话"（`namespace=SIMULATED`），
  **永远不进真实证据库**、不会变成"稳定性格"——但也没有单独的删除命令（见 §4 第 5 条）。
- **别把输出当权威设定**。档案是"这批材料支持的说法"，不是人物百科；对话模拟产出更不能当事实引用。

## 1. R1：G12 `traits` 重复条目（先做这个）

### 1.1 现状（已登记 `RUNNING.md` §5.16）

`_build_persona_draft` 按**证据**生成条目（`item_id = pi_<evidence_id>`），
跨源同句产生两条**文本相同**、各引一条证据的条目。不是 AC-7 违规
（每条都有证据），是**档案可读性**缺陷。

### 1.2 三个方案

| 方案 | 做法 | 影响面 | 主要风险 |
| --- | --- | --- | --- |
| **A（推荐）** | 条目身份改为**说法 + 主体**：`item_id = pi_<claim_key>`，`evidence_refs` 收全部 | `_build_persona_draft` + 版本 diff 口径 + 既有断言 | 旧档案条目 id 变了 → 版本比对会显示"删一条 + 增一条" |
| B | 仍按证据存，**出档时按文本聚合** | 只改 draft 构建 | "档案 = 证据投影"不变式失效，diff 口径要重新定义 |
| C | 只在**渲染层**去重 | 最小 | 库里仍是重复，消费方（对话、导出）照样读到两份 |

**推荐 A**，理由：档案条目的自然语义是"一条特征 + 若干证据支持"，
现在反过来（证据 → 条目）才会产生重复；AC-7 想要的正是"多源支持才算 traits"，
A 让"支持条数"变成可读的 `len(evidence_refs)`。

### 1.3 A 的诚实边界

A 只能合并**归一化说法完全相同**的同句（复用 `judge_stability` 已有的
"归一化说法 + 主体集合"分组键）。措辞略有差异的同义说法**仍会是两条**——
那是语义聚类（P1b，`D-G` 另立），不在 G12 范围内。

### 1.4 实际改动的测试（已落地，如实记录）

- `tests/test_p4_7_p1a_same_claim.py`：`test_cross_source_same_claim_lands_in_traits`
  从"2 条同文本条目"改为"**1 条 + 2 条证据引用**"；**新增** 2 项——
  `test_merged_item_id_is_stable_across_reruns`（重跑身份不变）、
  `test_only_whitespace_equal_claims_are_merged`（只差一个句号就不合并，钉住诚实边界）。
  该文件 6 → **8 项**。
- `tests/test_p4_5a_e2e.py`：`test_same_wording_from_two_sources_becomes_repeated` 与
  `test_step_persona_wires_judgement_end_to_end` 两处计数 2 → 1，并补
  "`evidence_refs` 必须是 2 条"的断言（**没有放宽**，反而多钉了一条）。
  该文件仍 **85 项**。
- 版本 diff 策略：**不做 id 迁移**（档案版本化，旧版本按原样保留）。

### 1.5 已定（用户拍板）

- 选 **A**；旧存档**不做** id 迁移；`item_id` 用**哈希**
  （`pi_<sha256(维度|归一化说法|主体)[:16]>`，避免 id 含超长中文，且跨进程稳定）。

## 7. R4 调用清单（本次要你确认的那份账）

按**仓库当前 `.env`** 的口径（`deepseek` + `tavily`、`max_extracts=1`、
单价 0.3 / 1.2 USD 每 100 万 token、est 3000 in / 2000 out）计算：

```
检索            : 2 次（模板查询，basic ≈2.0 credits）
抓取正文        : ≤1 次（`max_extracts` 上限；单条失败官方不计费）
模型调用        : 1 次抽取（批量） + 2 次对话
预估费用        : 模型 ≈0.009900 USD；检索 ≈2.2 credits
计量单位        : 检索按 credit、模型按 USD —— 两者不可直接相加
边界            : 清单之外不会有任何调用；出现清单外的调用即为缺陷
```

- **形态**：2 个目标（阿灯 / 阿雾，虚构角色 +《雾港灯会》2020 动画改编版），
  `max_rounds=1`，一次真实运行跑满五阶段；
- **模型侧**：单次估算 0.0033 USD × 3 次 = **≈0.0099 USD**；
- **检索侧**：2 credits（两次 search）+ 0.2 credit（≤1 次 extract）≈ **2.2 credits**。
  按公开价目表 $0.008/credit 粗算 ≈ $0.018，**但本系统不做换算**（账本只用 credit 记账）；
- **累计影响**：人工累计 0.0097980 → 约 **0.0197 USD**（仍是 0.25 单次上限的 8%）。

### ⚠️ 一个必须先改的配置

`.env` 现在是 `PERSONA_MODEL_MAX_CALLS=1`。本次计划要 **3 次**模型调用
（1 次抽取 + 2 次对话），按现在的配置会在第二次调用时被判
`BUDGET_EXCEEDED`，五阶段跑不完。

跑 R4 前需要你批准二选一：

| 方案 | 改动 | 模型调用 | 预估费用 | 代价 |
| --- | --- | --- | --- | --- |
| **A（推荐）** | `PERSONA_MODEL_MAX_CALLS=3`（保持 0.25 总额上限） | 3 | ≈0.0099 USD | 上限从 1 次放到 3 次，仅本次 |
| B | 单目标跑（不生成对话） | 1 | ≈0.0033 USD | 关系/对话两阶段按语义跳过，只验检索→证据→档案 |

### 授权边界

授权时我会明确三件事：**跑哪种形态（A/B）、改不改 `MAX_CALLS`、跑完给逐笔账**。
一次 POST 都不多打；任何重试都不会发生（`max_retries=0`）。

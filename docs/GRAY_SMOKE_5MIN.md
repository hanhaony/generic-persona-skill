# 干净环境 5 分钟冒烟清单（试用人先看这个）

> **目的**：在你**花第一分钱之前**，用 3 条零外呼命令确认环境是好的。
> 全程**不联网、不花钱、不碰你的数据**。全部跑完约 2 分钟。

---

## 第 0 步：安装是可选的

```bash
# 不需要 pip install —— 在仓库根目录下直接跑就行
cd generic-persona-skill
python -m persona info
```

`pip install -e .` **是可选的**，装不装都能用；没装就全程用 `python -m persona …`。

---

## 三步冒烟（按顺序，看退出码）

| # | 命令 | 该看到的 | 退出码 |
| --- | --- | --- | --- |
| 1 | `python --version` | **3.12+** | 0 |
| 2 | `python -m persona info` | 版本、Python 版本、包结构 | **0** |
| 3 | `python -m persona selftest` | `SQLite 读写 OK / 隔离闸门 OK / Mock Provider OK / 自检结论：通过` | **0** |

**第 2、3 步都是 0 = 环境没问题，可以往下走。**

两条重要说明：

- `selftest` 用的是**临时目录里的数据库**，**不会碰你任何项目数据**。
- `persona info` 打印的"当前阶段"应当是 **P6 二期完成（对话与记忆产品化，已验收）**，
  且说明里写着"真实检索与正文抓取**已接入并通过受控真跑验证**"。
  **如果你看到的是「真实检索未接 / 不接真实搜索 API / 尚未授权真实模型调用」这类旧字样，
  说明你拿到的是旧版本**——先告诉我，别继续往下跑。

### 一个坑：别用 `config check` 确认密钥

`python -m persona config check` **在没有密钥时也会返回 0**——它校验的是配置值本身，
不是"密钥在不在"。想确认密钥，往下看第 4 步。

---

## 第 4 步：设两把密钥（只认环境变量）

```bash
export PERSONA_SEARCH_API_KEY=...      # 检索（run 需要）
export PERSONA_PROVIDER_API_KEY=...    # 模型（run 与 chat 都需要）
```

> 密钥**只认环境变量**；写进 `.env` 会被忽略并告警（这是刻意设计：不鼓励把密钥落盘）。

---

## 第 5 步：`--dry` 看清单（零成本，也是密钥的最终验证）

```bash
python -m persona run --names "林黛玉,贾宝玉" --work-title 红楼梦 --dry
```

两种结果都正常：

**① 退出码 0** —— 打印"本次将要发出的真实调用"，含检索次数、模型调用次数、预估费用、
上下限，末尾是「（--dry：只打印清单，没有发生任何调用）」。看到这个，**密钥和环境都好了**。

**② 退出码 1** —— 打印：

```
拒绝运行：本次计划里没有任何检索（检索出口离线或没配密钥）。
  怎么办      ：设置 PERSONA_SEARCH_API_KEY（或 TAVILY_API_KEY）后重试。
  说明：本次**没有发起任何请求**。
```

**这不是坏了，是它在没钱可赚之前就停住了**。按提示补上检索密钥再跑一次即可。

> 只想先用 `chat` 的话，**只需要模型密钥**（`chat` 不发任何检索请求）——
> 但 `chat` 要求同一批人名**先跑过 `run`**。

---

## 好了，可以真跑了

第一次 `run` 会**先算账再问一次**：打印清单 → 问「继续？[y/N]」→ **直接回车 = N = 取消**（零调用）。
跟着「SKILL.md」的四行跑通走就好。

> 真跑会默认把数据库写在**仓库根目录下的 `var/`**（已被 `.gitignore` 忽略，不会进版本库）。
> 想写到别处就加 `--out <目录>`。这不影响使用，只是顺带告诉你它落在哪。
>
> ⚠️ 唯一的副作用：真跑之后，**在仓库根目录跑全量测试**时
> `test_all_data_in_temp_dir_not_user_data` 会红——它要求仓库根没有真实数据目录。
> **删掉 `var/` 即可，不是缺陷**。

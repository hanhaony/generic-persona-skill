### 标志性成果（这轮最值钱的一条）

P6.3 会话 A′ 的**第 1 轮**就检索到了 `mem_b1036f…`——那是 **P6.2-d 会话 A** 写下的旧记忆，
两者相隔一天、进程不同、命令行参数也不同：

```
P6.2-d 会话 A 写记忆 → 落库（SIMULATED / SESSION / ACTIVE）
        ↓ 换天、换进程
P6.3  会话 A′ 带 --topic 开会话 → 第 1 轮命中 → referenced_memory_ids 非空
        ↓
P6.3  会话 B′ 同 topic 问"你还记得我说过在读什么书吗？" → 答出"西厢记/崔莺莺"
P6.3  会话 C′ 换 topic"青埂峰"（输入逐字相同）→ 检索为空、仍拒答（没被污染）
```

即「**写入 → 持久化 → 跨进程 → 跨会话 → 被模型用上**」整条链是通的，
而 C′ 证明这个"记得住"是**有条件**的：条件不满足就取不到，不会把无关记忆塞进上下文。

## 二、已知局限（12 条完整版在 `docs/RUNNING.md` §5.44.3）

挑**会影响灰度用户体验**的五条，发邀请前自己先看一遍：

1. **没有记忆管理命令**：`persona memory` 仍是占位 → 写进去的模拟记忆**没法从 CLI 查看或清理**，
   只能直接读库。**这条最可能招来"我写进去了却看不见"的反馈。**
2. **默认一条记忆都不写**：必须显式 `--memory-write rule`；换会话想让它想起来还得加 `--topic "X"`。
   三层都是刻意设计，但用户会当成 bug。
3. **`PERSONA_MODEL_MAX_CALLS` 只数本次进程**（默认 3）→ 会拦住 `--rounds 4` 的对话，
   退出码 1、**零调用**。绕法是进程级环境变量，别改 `.env`。
4. **判据是字面规则、会脆**：五维评估出现过"模型答对了但被判 FAIL"，所以
   **自动判据只是第一道筛子，必须人工复核**。
5. **`task_id` 恒 null**（`run` 与 `chat` 都一样）→ 账单无法按任务对账，只能查 `usage_records.scope`。

## 四、阶段三清单

### P7.0 灰度测试（建议**先做这个**）

**目标**：让 3-5 个真实用户**在没有我在旁边解释**的情况下自己跑完 `run` + `chat`，回答三个问题：

| 问题 | 想搞清楚什么 |
| --- | --- |
| Q1 | 三步里哪一步会**自己崩 / 被误解**？（安装、密钥、确认问句、`MAX_CALLS`） |
| Q2 | 他们会**怎么用**（尤其 `--topic` 的用法、会不会期待"自动就该记住"） |
| Q3 | 哪些**刻意设计被当成 bug**？（默认不写记忆、要显式 topic、拒绝没有档案的人名） |

#### 找谁（5 个，按类型配）

| # | 类型 | 人数 | 会暴露什么 |
| --- | --- | --- | --- |
| 1 | 熟命令行、**不熟本项目**的人 | 1-2 | 上手路径、`README` / `SKILL.md` 有没有写清楚 |
| 2 | 角色扮演 / 写作爱好者（`chat` 的目标用户） | 1-2 | 对话质量、"记住"的体验是否符合预期 |
| 3 | 做过 LLM 应用或产品的人 | 1 | 拿苛刻标准挑刺，包括安全与成本口径 |
| 4 | （可选）完全不看文档就上手的人 | 1 | 纯劝退点；**第一批先用 1-2 人，别一开始就上 5 个** |

**明确不要**：只用 GUI 的人（本期没有 Web UI）；**不要拿身边的人当素材**（隐私红线，见下）。

#### 节奏（两周）

| 天 | 做什么 |
| --- | --- |
| D1 | 发 `SKILL.md` + `GRAY_RELEASE.md` 给**第一批 2 人**；我这边准备"干净环境 5 分钟冒烟清单"备用 |
| D2–D5 | 他们自己跑（约 1 小时/人），**中途不主动答疑**，除非被问 |
| D6 | 收第一批反馈 → **先改文档**（大概率是文档问题而非代码问题） |
| D7–D10 | 再放 3 人 |
| D11–D12 | 汇总，产出 P7.1 的优先级清单 |

**为什么分批**：第一批大概率暴露的是"文档没说清"，修完再放第二批，第二批才会给出真正有价值的产品反馈。

#### 成本（**灰度用户自带密钥，我不代办、不出钱**）

每人：1 次 `run` ≈ **0.0078 USD + 3 credits**（检索 2 次 + 正文抓取 4 篇）+ 3-6 轮 `chat` ≈ **0.002 USD**。
5 人合计 ≈ **0.05 USD + 15 credits**。极便宜，真正的成本是**时间**。

#### 反馈格式（五样 + 三问）

复用 `GRAY_RELEASE.md` §5 的五样：**命令原文 / 退出码 / 输出片段（首尾各 20 行，别只截 Error 一行）/ Python 版本+系统 /
（自愿）`persona.db`**。另外请回答三个问题：

1. **卡在第几步**？是先不懂（文档）还是跑不通（代码）还是通了但结果不对（质量）？
2. **有没有哪个行为你以为是 bug**（后来发现是设计）？写下来——那就是下轮要改措辞的地方。
3. **最想要的下一个功能是什么**？（记忆管理命令 / topic 自动提取 / 流式输出 / 别的）

#### 灰度"通过"的判据（**先写死，别到时候争论**）

- ≥ **3/5** 人在**无人协助**下跑完第 1、2 步；
- 收到 ≥ **5 条具体**反馈（不是"还行"、"挺好的"）；
- **硬阻塞 ≤ 1 个**（"零调用就无法继续"那种）。有 2 个以上 → **停止扩量**，先修。

**不追求**："大家都说好用"。3-5 人的样本不配当满意度调查。

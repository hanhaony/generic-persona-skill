# P6.3：给 `persona chat` 一个 topic 入口（**方案，未实现**）

> 本文只出方案，不改代码。等拍板后再实现。
> 起因：P6.2-d 真跑对账（RUNNING §5.42）的分层结论——
> **R1 本会话检索已在产品路径生效；R2 跨会话"代码在、永不触发"，
> 缺的是 `chat` 没有 topic 入口，不是检索能力。**

---

## 1. 先说清"缺的是什么"

`_retrieve_memories`（`modules/dialogue.py:1239`）两条规则的现状：

| 规则 | 条件 | 产品路径 | P6.2-d 实测 |
| --- | --- | --- | --- |
| R1 本会话 | `scope=SESSION` + `scope_id=本会话`，**无条件** | ✅ 已生效 | 会话 A 第 3 轮起 `referenced_memory_ids` 非空 |
| R2 跨会话 | 参与者相交 **且 `topic` 非空** | ❌ 永不触发 | 会话 B 全部 `[]` |

`persona chat` 的 `SessionDraft` 从来不传 `topic`（CLI 也没有这个参数），
所以 `topic` 恒 `None` → R2 的 `if topic and str(topic).strip()` 永远为假。

**要修的是入口，不是规则。** 「无 topic 不取」是刻意设计（防无关记忆无条件进
上下文，用户目标 4），本次**不放宽**：R2 的条件一个字都不改。

**检索能力已经够了**——P6.2-d 已实测：直连 `MemoryService.search` 用 R2 形态
查询（text + 参与者）能查到会话 A 的记忆。缺的只是"有没有人把 topic 传进来"。

---

## 2. 决策点 ①：topic 从哪来

三个选项，先给结论：**本次只做显式传入；自动提取列为 P6.3-b，且必须另出方案。**

### 2.1 显式传入（推荐，本次做）

```
persona chat --names "林黛玉,贾宝玉" --topic "西厢记" --rounds 3
```

- **确定性**：topic 就是用户敲的那串字符，可复现、可对账、可写进真跑报告。
- **零额外调用**：不碰模型，费用口径不变（仍是"轮数 = 调用数"）。
- **可审计**：授权清单里能打印出来（与"要花多少钱"同一屏）。

### 2.2 自动提取（本次不做，理由如下）

不装依赖 → **没有中文分词器**（jieba 属第三方，纪律不许装）。规则法只能做到：

1. 书名号/引号优先：`《…》`、`「…」` 内的内容直接当 topic（最具体）；
2. 否则按标点与停用词切分，取长度 ≥2 的最长片段；
3. 提取不到 → `topic=None`（静默，不打断对话）。

这条路**本身可行**，但有两个问题让它不适合和入口绑在一起做：

- **正确性无法用单测保证**：中文无分词器，"我现在觉得你比从前可亲多了"这类
  句子提不出有效 topic（或提出"觉得"这种词）。召回低可以接受，**取错不能接受**。
- **它是典型的 D 家族形状**：把"要不要跨会话召回"这个**语义决策**交给启发式
  规则的**默认值**。本项目已经为这个形状付过四次学费（D-A/D-B/D-D、以及
  P6.2-b 的"`none` 下不许派生"）。

**若要做，另行出方案**，并附两条硬验收：离线探针 ≥20 句、**污染率必须为 0**
（宁可全部不取，也不能取错一条）。

### 2.3 共存方式（如果将来做自动）

- `--topic <文本>`（显式）与 `--topic-auto`（自动）**互斥**；
- 同时给 → **报错退出**（不静默选一个，D-298 原则：同一个决策只在一个地方做）；
- 都给不了有效 topic → `topic=None` → R2 不触发，行为与今天完全一致。

**CLI 形态**：用**一个** `--topic` 参数 + 一个 `--topic-auto` 开关，
不用 `--topic auto` 这种魔法值（魔法值要靠字符串比较，容易在转发层写歪）。

### 2.4 一个实现约束（自动方案必须先解决）

`topic` 是**会话级**的，`start_session` 时就定下来；而"用户第一句"要到
`run_round` 才知道。所以自动方案必须**先读第一行再开会话**：

```
读首行 → 提取 topic → start_session(topic=…) → 把首行当第 1 轮喂进去
```

这会把 `_cmd_chat` 的开场顺序改掉（现在是先开会话再读 stdin）。**显式方案不受
影响**，这也是先做显式的另一个理由。

## 3. 决策点 ②：不破坏「无 topic 不取」

### 3.1 防线的位置：领域层，且只有一处

防线**不能只放在 CLI**——只放 CLI 等于"能力只存在于一条调用路径"，绕过 CLI
的调用方（脚本、评估、将来的 API）都能塞一个坏 topic 进去，正是 D 家族的形状。

做法：**一个纯函数，两处用法**（判断逻辑只写一遍，符合 D-298）：

```python
TOPIC_MIN_LEN = 2
TOPIC_MAX_LEN = 64
TOPIC_STOPWORDS: tuple[str, ...] = (...)   # 的/了/我/你/他/这/那/是/在/有/吗/呢/吧…

def topic_is_retrievable(topic: str | None) -> bool:
    """这条 topic 够不够具体，值不值得据此去跨会话取记忆。"""
```

| 调用点 | 用它做什么 | 语义 |
| --- | --- | --- |
| `start_session` | 不合规 → **Err** | 用户**显式**给了坏 topic：报错，不静默丢弃 |
| `_retrieve_memories` | 不合规 → **跳过 R2**（不是 Err） | 读路径不能因为一条脏数据让整轮失败；老会话行的 topic 不合规时按"没有 topic"处理 |

`topic is None` → 两个调用点都直接放行"不取 R2"，**与今天完全一致**。

### 3.2 已确认不受影响的两条链路

- **评估链路**：`scripts/run_dialogue_eval.py:294` 的 `start_eval_session`
  根本不传 `topic` → 恒 `None` → 新校验不会打到它（**已查证，不是推测**）。
- **P6.2 用例**：`chat` 不传 `--topic` 时行为零变化。

### 3.3 要钉死的测试

| 场景 | 断言 |
| --- | --- |
| 会话 `topic=None` | `memory_reader.search` **只被调用 1 次**（只有 R1 那条查询），第二次带 `text` 的查询**不发生** |
| 会话 `topic="  "`（空白） | 同上：不触发 R2 |
| 历史会话行被塞了坏 topic（绕过 `start_session` 直接写库） | `_retrieve_memories` 跳过 R2，只查 R1 |

第三条是**关键**：它保证防线在"入口之外"也成立，不只是挡住 CLI。

> 说明：`tests/test_dialogue_memory_integration.py::test_no_topic_means_no_cross_session_pull`
> 已经钉住了"无 topic 不跨会话"的**服务层**行为。本次新增的是**检索端口层**
> 的断言（查了几次、参数是什么）——补的是"它根本没去查"，比"查了没查到"更强。

## 4. 决策点 ③：取错了不污染

### 4.1 先看清楚匹配算法的真实形状

`MemoryService._matches`（`modules/memory.py:1176`）：

```python
terms = [t for t in str(text).split() if t]      # 按**空白**切
return all(t.lower() in cl for t in terms)        # 子串包含，全命中才算
```

两条直接后果：

1. **中文 topic 是整串当一个 term**：`topic="西厢记"` → 在 content 里找
   "西厢记" 子串。_topic 越短，命中面越大_：`topic="我"` 会命中**每一条**
   含"我"的记忆（我们的记忆几乎都含"我"）。
2. **`_score` 救不了宽 topic**：单 term 命中时 `base` 恒为 1.0，
   score 只反映 salience 与新旧，**不反映 topic 的宽窄**。加 score 阈值是
   假防线——它砍不掉"宽 topic 命中一堆"。

**结论：真正的门禁只能做在 topic 本身（质量），不能做在命中之后（打分）。**

### 4.2 topic 质量门禁

#### 4.2.1 停用词表（**明确列出**，不是"停用词表"四个字）

```python
TOPIC_STOPWORDS: tuple[str, ...] = (
    # 代词
    "我们", "你们", "他们", "她们", "它们", "咱们",
    "我", "你", "他", "她", "它", "其", "某",
    # 虚词 / 助词 / 连词 / 介词
    "一个", "这个", "那个", "这么", "那么", "这样", "那样",
    "的", "了", "是", "在", "有", "和", "就", "都", "而", "及",
    "与", "着", "或", "也", "很", "太", "还", "再", "又", "把",
    "被", "给", "对", "从", "向", "到", "过", "吗", "呢", "吧", "啊",
    # 疑问词
    "什么", "怎么", "为什么", "怎样", "如何",
    "哪", "谁", "几",
)
```

**匹配语义（关键，比词表本身更重要）**：不是"topic 里出现停用词就拒"，
而是 **从 topic 里剥掉所有停用词（按长度降序剥离，保证"我们"先于"我"被剥），
看剩下的还剩下什么**：

| 输入 | 剥离后 | 判定 |
| --- | --- | --- |
| `我` | ``（空） | ❌ 拒：太宽泛（去停用词后为空） |
| `我读了本书` | `读本书` | ✅ 放行（3 字，有信息） |
| `我们的西厢记` | `西厢记` | ✅ 放行 |
| `西厢记` | `西厢记` | ✅ 放行 |

为什么是"剥离后判空"而不是"出现即拒"：`我们的西厢记` 是**很具体**的话题，
出现即拒会误杀；而 `我` 剥完什么都不剩，才是真的没有信息量。

#### 4.2.2 约束与判定顺序

| 序 | 约束 | 取值 | 不合规时 |
| --- | --- | --- | --- |
| 1 | 空白 | `strip()` 后为空 → **视为无 topic** | **不报错**，与 `None` 同口径（用户没说要跨会话） |
| 2 | 停用词 | 剥离后为空 → 拒 | `Err` + 错误码 `VALIDATION_TOPIC_TOO_BROAD` |
| 3 | 最小长度 | 剥离后 `len >= 2` | `Err` + `VALIDATION_TOPIC_TOO_SHORT` |
| 4 | 最大长度 | 原值 `len <= 64` | `Err` + `VALIDATION_TOPIC_TOO_LONG` |

长度判定用**剥离后的残留**（它才是携带信息的部分）；最大长度用**原值**
（防止把整段话当 topic）。多词 topic（"西厢记 崔莺莺"）按空白切成 AND——
**天然更严**，不需要额外约束。

#### 4.2.3 错误信息（**明确写出**，不写"报错"两个字）

领域层（`start_session` 的 `Err.message`）：

```
topic "我" 太宽泛：去掉停用词后什么都没剩，请换一个更具体的话题（例如「西厢记」）
topic "书" 太短：至少 2 个字（去掉停用词后计算），请换一个更具体的话题
topic "<65字以上>" 太长：最多 64 个字，topic 是话题标签，不是整段话
```

CLI 层（`--topic` 校验失败，用户显式传的坏值 → **报错退出，0 次调用**）：

```
ERROR: topic "我" 太宽泛（命中停用词）：请换一个更具体的话题。
  例如：--topic "西厢记"
  说明：本次**没有发起任何请求**。
```

分层（用户拍板确认）：

- **用户显式传坏 topic → CLI 层报错退出（0 次调用）**，钱一步都不动；
- **历史脏 topic（绕过 `start_session` 直接写进库的行）→ `_retrieve_memories`
  跳过 R2，不让整轮失败**（读路径不能因为一条脏数据挂掉）。

### 4.3 「取错不污染」的测试（本次必须新增）

| 场景 | 断言 |
| --- | --- |
| `SessionDraft(topic="我")` | `start_session` → **Err**（不静默丢弃用户显式给的值） |
| `SessionDraft(topic="的")` / `"这个"` / `"什么"` | Err（停用词剥离后为空） |
| `SessionDraft(topic="")` / `"   "` | 不报错，`topic` 视为空 → 不取 R2 |
| `SessionDraft(topic="书")` | Err（太短：1 字） |
| `SessionDraft(topic="我们的西厢记")` | **放行**（剥离后 = "西厢记"，见 §4.2.1） |
| 库里有"西厢记"记忆 + 无关记忆（"集市上的雨伞…"），`topic="西厢记"` | 命中前者、**不命中后者**（prompt 里没有无关内容） |
| `chat --topic "我"` | CLI 报错退出，**0 次模型调用** |

最后一条最重要：**坏 topic 必须在花钱之前被拦住**。

> 已存在的覆盖（不重复造）：`test_unrelated_memory_never_enters_context`
> 已测"话题不符 / 对象不符 / 真实命名空间"三类不进上下文。本次只补
> **topic 太宽**这一类。

### 4.4 边界语义：**近宽**与**拼错**（用户要求明确设计意图）

门禁只回答一个问题：**这条 topic 的信息量够不够让它去跨会话取东西**。
它不回答"词完不完整""有没有拼错"——那两个是检索结果的问题，不是门禁的问题。

| 输入 | 门禁 | 检索 | 结果 | 设计意图（**明确**） |
| --- | --- | --- | --- | --- |
| `topic="西厢"`（2 字、非完整词、子串会命中"西厢记"） | **放行** ✅ | 命中"西厢记"记忆 | 注入 | **拦了才是错**。门禁不管词完不完整：2 字、非停用词、在子串匹配下命中的**就是**西厢记相关的记忆，不会污染。用户就是想聊西厢，凭什么拦他 |
| `topic="西厢记记"`（拼错） | **放行** ✅ | **0 命中** | 注入为空，**不报错** | 拼错属于"**取不到**"，不是"取错"。系统**不猜用户意图**（不纠正、不模糊匹配），也**不假装出错**。空结果与"无 topic"同效：不注入任何东西，因此**不污染** |

一句话：**门禁拦"宽"，检索回报"空"，两者都不制造污染**。
归入 §6 的测试用例：`test_short_but_specific_topic_passes`、
`test_misspelled_topic_passes_gate_but_retrieves_nothing`。

#### 4.4.1 实测（对**真实库**跑一遍，零外呼，方案阶段已完成）

不是推理，是量出来的。用 P6.2-d 留下的 2 条记忆，按 R2 形态查询
（`text=topic` + 参与者 + SIMULATED + ACTIVE）：

| topic | 命中 | 门禁应当 | 实测是否印证设计 |
| --- | --- | --- | --- |
| `西厢记` | **1 条**（西厢记那条） | 放行 | ✅ |
| `西厢`（近宽，2 字非完整词） | **1 条**（同一条，子串命中） | **放行** | ✅ 印证"拦了才是错"：它命中的就是西厢记相关记忆 |
| `西厢记记`（拼错） | **0 条** | 放行 | ✅ 印证"取不到 ≠ 取错"：空结果，不污染 |
| `青埂峰` | **0 条** | 放行 | ✅ C′ 的预期由此坐实 |
| `崔莺莺` | 1 条 | 放行 | ✅ |
| **`我`（宽）** | **2 条 = 全部记忆** | **拒** | ✅ **"宽 topic 会污染"不是理论**：一个字就把两条全捞进来了 |
| `书`（1 字） | 0 条（本库恰好不含） | 拒（太短） | 长度门禁照拦：本库没污染不代表别的库不会 |

`topic="我"` 那一行是整份门禁设计的**实证依据**：在子串匹配下，单字 topic
能命中库里**每一条**记忆。所以 §4.2 的最小长度与停用词表不是保守，是必需。

## 5. 决策点 ④：跨会话验证场景（A → B → C）

### 5.1 一个省钱且更有说服力的改动：复用 P6.2-d 的对照组

P6.2-d 已经在真实库里留下 **2 条记忆**，其中一条正是
`mem_b1036f… = "我在读《西厢记》，觉得崔莺莺这个人挺有意思"`（`scope_id=会话A`）。
而 P6.2-d 的会话 B 问过一句 **"你还记得我说过在读什么书吗？"**，模型答的是
**"资料没写：我这儿没有你先前说过在读什么书的记载"**。

**这就是现成的失败基线。** P6.3 用**同一句输入**、只加 `--topic`，前后对照：

| 会话 | 命令 | 输入 | 预期 |
| --- | --- | --- | --- |
| **A′** | `chat --topic "西厢记" --memory-write rule --rounds 2` | 见下（**写死**） | 写入 1 条；验证"带 topic 的写入侧"也跑得通 |
| **B′** | `chat --topic "西厢记" --rounds 2` | 第 1 句照抄 P6.2-d 那句"你还记得我说过在读什么书吗？" | `referenced_memory_ids` **非空**；模型答出"西厢记/崔莺莺"（不再说"资料没写"） |
| **C′** | `chat --topic "青埂峰" --rounds 2` | 同一句 | `referenced_memory_ids` **为空**（无匹配记忆，**不注入无关内容**）；模型仍拒答——**这是对的** |

同一个问题、同一批数据、只有一个变量（topic），**结论的因果最干净**。

#### A′ 的输入（**写死，与 P6.2-d 会话 A 同一句话，便于对照**）

| 轮 | 输入 | 规则预期 | 说明 |
| --- | --- | --- | --- |
| A′1 | `你好` | **N2 寒暄 → 不记** | 与 P6.2-d A1 同一句 |
| A′2 | `我在读《西厢记》，觉得崔莺莺这个人挺有意思` | **R-EPI → EPISODIC，记 1 条** | 与 P6.2-d A2 **同一句**，因此 A′ 应当复现出"同内容、不同 `scope_id`"的一条新记忆 |

A′ 的判定：写入 **1 条**（不是 2 条）、`content` 与原话一字不差、
`namespace=SIMULATED` / `scope=SESSION` / `scope_id=A′的会话 id`。
选同一句话的代价是它**不会**与 P6.2-d 的 `mem_b1036f` 去重（dedupe 键含
`scope_id`，跨会话本就不去重，属已知设计）——所以预期就是"多出一条同内容的
记忆"，**不是重复写入缺陷**。

#### B′ / C′ 的输入（写死）

| 轮 | 输入 | 规则预期 |
| --- | --- | --- |
| B′1 / C′1 | `你还记得我说过在读什么书吗？` | **N1 问句 → 不记**（两句都只问不写，避免新记忆干扰对照） |
| B′2 / C′2 | `我最近常去梨香院听戏` | 无 cue → 不记 |

B′ 与 C′ **输入完全相同**，唯一变量是 `--topic`。

### 5.2 验收标准：**两层**（用户拍板，缺一层不算验完）

判定按 P6.2-d 的分层口径，但**真跑的验收只看两层**，且两层的含义不同：

| 层 | 判什么 | B′ 预期 | C′ 预期 | 拿什么判 |
| --- | --- | --- | --- | --- |
| **第一层：检索层** | R2 被触发、记忆被**注入** | `referenced_memory_ids` **非空**（含 `mem_b1036f` 或 A′ 新写的那条） | **为空**（无匹配记忆） | 落库的 `ConversationTurn.referenced_memory_ids` |
| **第二层：行为层** | 模型**用上了**注入的记忆 | 回答里出现"西厢记/崔莺莺"，**不再说"资料没写"** | 仍拒答——**这是对的**（没被污染） | 回答原文，**人工复核**（P6.0 口径） |

**两层不一致时的归属规则（明确）**：

- **第一层过、第二层不过** → 这是 **prompt 问题**（记忆注入了但模型没用上），
  **不是 P6.3 的检索问题**。P6.3 **照常判定为通过**，把"注入了没用上"
  **单独记录为已知局限**（照 P6.0 里 E1 的处理方式：人工记录原因、不阻塞、
  不为此放宽判据）。
- **第一层不过** → 这才是 P6.3 的失败：要么入口没把 topic 传进去（接线问题），
  要么门禁误杀（topic 质量问题）。**必须定位根因，不追加调用**。

第二层为什么不写成自动断言：模型"有没有用上"是语义判断，做成关键词断言会
重犯 P6.0 里 judge  brittleness 的老毛病（措辞漂移 → 断言失效）。所以**自动
只钉到第一层**，第二层由人看原文、把结论写进报告。
